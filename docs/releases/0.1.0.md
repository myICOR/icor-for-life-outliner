# ICOR for Life - Outliner 0.1.0

The first release: the core engine, the keyboard layer, thirteen
commands, whole-item selection, drag and drop, folds that can live in the
file, and the settings. Lists in the editor behave like an outline.
Nothing about how a list looks changes, apart from a drop line while you
drag; the theme owns the rest.

## What it does

- **Tab and Shift-Tab move the whole item.** The item and everything under
  it go under the previous sibling, or out to right after the parent. The
  indentation is whatever the list already uses, read from the neighbours,
  and the editor's own unit only when the list gives no hint. A list that
  mixes tabs and spaces is refused rather than guessed at.
- **Enter knows about children.** At the end of an item with children the
  new item is the first child; mid-line, the tail and the children follow
  the new item; on an empty nested item, Enter outdents instead of
  doubling. A task box is carried over, unchecked. Enter steps aside inside
  frontmatter, code blocks (fenced or indented), tables, callouts, quotes,
  HTML blocks and math blocks, decided by the editor's syntax tree.
- **Backspace and Delete never eat a bullet.** At the content start they
  merge two items only when that cannot lose structure (see the README
  table) and otherwise do nothing. Mod-Backspace on macOS deletes back to
  the content start and stops.
- **The cursor stays in the content** and out of folded blocks, on every
  move, whatever moved it. ArrowLeft at the content start jumps to the end
  of the previous visible line.
- **Select all climbs**: the item, then the item with its children, then
  the whole list, then the note.
- **Shift-Up and Shift-Down select whole items**, each with its subtree,
  and grow or shrink the selection sibling by sibling. Tab, Shift-Tab,
  move up, move down, delete with subtree, duplicate, toggle done, expand
  all and collapse all then work on every selected item as one change and
  one undo step, and the selection stays on them.
- **Mod-Shift-Enter inserts an empty item above** the current one, same
  indent and bullet, without touching it.
- **Thirteen commands** with icons and a default hotkey each: fold,
  unfold, expand all, collapse all, move up, move down, indent, outdent,
  insert above, delete with subtree, duplicate, toggle done, and move
  to, which opens a picker of every heading and list item in the file
  and reparents the item under the chosen one. They carry the same
  behaviour to the command palette and the mobile toolbar. Folds survive
  every move.
- **Drag and drop on desktop.** Press on a bullet and drag the item with
  everything under it before or after another item of its list, or into
  one as its first child. Escape cancels; a note that changed under the
  drag aborts with a notice; a pop-out window is wired on the first
  press in it and then works like the main one. One edit, one undo step.
- **Folds can live in the file.** Off by default: with "Remember folds in
  the file" on, a folded item carries a `%% fold %%` comment at the end
  of its line (before a trailing block id, so block links keep working)
  and the plugin folds it again on open, on any device. The comment is
  hidden in reading view and shows faint in Live Preview and source mode.
  With the setting on, opening a note also writes markers for folds
  Obsidian already remembers that the file does not, and so does the next
  edit in a list. Markers already in a file are honoured either way.
- **Ordered lists count again** after every structural change.

## Default hotkeys

Every command ships with a default hotkey, changeable under Settings,
Hotkeys: Mod+Alt+ArrowUp and ArrowDown fold and unfold, with Shift added
they collapse and expand the whole subtree; Mod+Shift+ArrowUp and
ArrowDown move the item; Mod+] and Mod+[ indent and outdent; Mod+Shift+A
inserts above; Mod+Shift+Backspace deletes with the subtree; Mod+Shift+D
duplicates; Mod+Shift+L toggles done; Mod+Shift+M opens the move-to
picker. The full table with the reasoning is in the README.

The decision and the reason. The community directory's guideline (and
its `no-default-hotkeys` lint rule, which stays on at warning level)
says a plugin should ship without default hotkeys. This build ships with
them by Tom's directive of 2026-09-06: it is a vault build for testing
and refinement, not a directory submission, and a set of commands nobody
can reach from the keyboard without a trip to the Hotkeys page is not
testable. Obsidian lets every user change or remove each one, which is
what "changeable to their liking" means here. Two facts from the 1.13.7
bundle shaped the chords: Obsidian's hotkey layer runs on the window in
the capture phase and consumes a bound chord whether or not the command
did anything, so a default hotkey never falls through to the editor;
and six of the natural chords are editor keys (add cursor above and
below, indent and outdent the line, and on macOS select to the start and
end of the note). Those six commands do the editor's job themselves when
the cursor is not in a list, through the public API, so nothing is lost
outside a list. Every chord is checked against the app's own default
hotkey list and its editor keymap, both pinned as data in
`test/manifest.test.mjs`. Mod+ArrowUp and Mod+ArrowDown are not used: on
macOS they go to the start and end of the note.

## Settings

Keep the cursor in the content (never, after the bullet, after the bullet
and the checkbox), Tab moves the whole item, Enter knows about children,
Select all climbs, Shift-Up/Down selects whole items, Drag and drop
(desktop only, hidden on mobile), Remember folds in the file (off),
Debug logging, plus two read-only groups: "Keyboard shortcuts" (the
thirteen commands with their default hotkeys and where to change them)
and "Editing keys" (the keys that are not commands and the toggle that
switches each). Settings appear in Obsidian's settings search.

## Not in this release

Guide lines, drag between two lists (move to covers it from the
keyboard), Vim bullets and a zoom hook. Each has a place reserved in the
code (see the README's "Development" section).

## Follow-up if the beta asks for it

**Open-time marker writes.** Obsidian restores a note's remembered folds
on open with plain fold effects, and with "Remember folds in the file"
on, the marker filter treats them like any other fold: the note is
written on open when Obsidian remembers a fold the file does not, and
Mod-Z right after opening removes those markers. For 0.1.0 this is the
documented behaviour (decision: Larry, 2026-09-06, Flint's option a).
If the beta shows the writes are annoying under git, the follow-up is a
settling-window guard: `applyMarkersOnOpen` in `src/editor/foldMarkers.ts`
records its view in a module-level `WeakSet<EditorView>` in its
constructor and removes it in its microtask, and the marker filter reads
`tr.startState.field(editorEditorField, false)` and returns the
transaction untouched while that view is settling. That closes the
open-time write; the double write on a mode switch would remain.

**The marker's look in Live Preview.** The word `fold` shows faint at the
end of a folded item in Live Preview and source mode. Whether anything
should hide it is Iris's call; if so, the plugin adds a `Decoration.replace`
over its own marker when the cursor is off the line (a `ViewPlugin` in
`src/editor/`), and the theme styles nothing.

## Reviewed against the 1.13.7 bundle

Before this build, Flint read the phase 1 snapshot against Obsidian
1.13.7's own code. Everything he found is in this version: the plugin
now checks, through the public API only, that the view it runs in
belongs to the Editor it was handed, and steps aside inside a Live
Preview table cell; Tab, Shift-Tab, Enter and Mod-Shift-Enter sit at
Prec.high, below the image editor's keys and above core's list keys;
the syntax-node classifier requires the list-line class, so math blocks,
indented code and HTML blocks no longer read as lists; the cursor filter
skips the editor's own `set` transactions; the settings page has no
dead fallback. The default command hotkeys were checked against the
bundle's default hotkey list and its editor keymap, and the thirteen
icon names against its Lucide set.

## Not verified outside the test suite

This version was built and gated without a running Obsidian. The parts
that only a live vault can settle (the fold-marker filter against the
fold gutter, the drag hit-test against Live Preview's bullet widget, the
Shift-Up/Down precedence against the editor's own keymap, the fold
restore on open, the table-cell pairing check against a real cell
editor, the registry after the edit mode re-initialises on a DOM move,
the time the move-to picker takes to open on a note of ten thousand
lines, a drag in a pop-out window, a block link through a folded marked
item, the file's modified time after opening a note with remembered
folds) and the two device tests (an iPad caret-handle drag across a bullet,
Android Enter mid-composition) are the first beta round's check.

## Requires Obsidian 1.13.0

The floor is the core this plugin was proven against, not the oldest
core its API calls would run on. It shadows the editor's own list keys
and hands back to them on every pass, sits below the 1.13 Live Preview
image editor's keys on purpose, and steps aside inside the 1.13 table
cell editor; a plugin that shadows core keys is coupled to the core it
shadows. The settings page uses the 1.13 declarative API and carries no
fallback for older apps.

## Install

Copy `main.js`, `manifest.json` and `styles.css` from this release into
`.obsidian/plugins/icor-for-life-outliner/` and enable the plugin under
Settings, Community plugins. Requires Obsidian 1.13.0 or newer. If another
plugin in your vault also binds Tab and Enter inside lists, disable one of
the two: whichever loaded first wins, silently.
